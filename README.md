# virtual-product-positioning

小红书虚拟产品机会诊断器（V2 需求优先架构）。

帮普通人从真实市场需求出发，找到被行为证据验证的具体付费任务，形成产品假设并完成 7 天小规模验证，再判断这个机会能否由当前用户长期稳定交付——最终落成"真实有人需要、这个人又做得出来"的虚拟产品。

## 核心架构

**总原则**：先证明"有人需要"，再证明"我能交付"，最后才证明"这是否适合成为我的长期优势"——需求 → 验证 → 交付 → 沉淀优势。

| 门 | 回答的问题 | 位置 |
|---|---|---|
| 前门：机会是否值得验证 | 有没有真实的人，正在为这个具体任务寻找解决方案？ | Phase 1-3（需求发现 → 任务收窄 → 定位收敛） |
| 中门：能不能安全验证 | 有没有致命条件导致实验根本不该启动？（合规红线/时间/绝对障碍） | 7 天验证前的轻检 |
| 后门：为什么由我来做 | 这个已验证的机会，能否转化成用户自己的长期产品？ | Phase 4 能力审计（动作级，非天赋级） |

关键设计：
- **需求优先于优势**——用户说不清"我擅长什么"不阻塞探索；个人承接资格不是前置门槛（验证前只查硬阻断，验证后才做能力审计）
- **需求结构 ≠ 需求证据**——高频结构特征与外部行为证据分开记录，不混层
- **候选数量由证据决定**——付费场景 6-8、定位假设 3 都是上限不是目标，可为 0
- **证据命题唯一性**——一条证据只证明它对应的命题，不自动证明邻近命题
- **优势从交付反推**——优势是验证周期中沉淀的行为数据，不是自我描述

## 使用

安装到 Claude Code：将本仓库 `skill/` 目录内容放入 `~/.claude/skills/virtual-product-positioning/`，或使用打包好的 `.skill` 文件。
