# 定位行动报告模板

virtual-product-positioning 的最终输出模板。输出报告前必读本文件。

## 核心纪律

**报告的详细程度不得超过证据的详细程度。** 每个关键判断标注来源——用户原话（引述）/ 外部信号（说明信号层级）/ 推断（写明依据）。追不回用户事实或外部信号的判断，只能作为待验证假设写进待实查，不写成结论。没有数据的地方不为了"显得完整"自行补齐。

**Evidence Audit（输出前必过）**：对每个关键判断检查来源——用户事实 / 外部信号（哪一层）/ 模型推导。找不到来源的降级为推断或待实查；连推断依据都没有的删除。**命题唯一性**：一条证据只证明它对应的那个命题，不自动证明邻近命题（"有人买作文资料"≠"三年级家长有需求"≠"这个用户做能卖"）——写证据时标清它证明的是哪一个命题。高危判断（用户愿意付费 / 市场规模 / 用户偏好 / 产品优于免费AI / 某价格合理 / 内容一定能转化）逐个过——"39.9能成立""用户要的是X"这类伪确定性不允许出现。

**跨阶段证据污染禁令**：报告中的合理推断（🔶）不得因为写进了报告就升级为"已验证"（✅）——"🔶用户可能重视节省时间"不会因为出现在报告里就变成"✅用户重视节省时间"。证据状态只能被 Validation 后的新行为证据改变，报告本身不产生证据。

## 报告结构（五部分，顺序固定）

### 一、需求任务地图

需求优先架构的第一部分是市场侧，不是个人侧。已发现的需求信号，**结构特征与行为证据分开标注**（"孩子经常不会作文"是结构描述，"家长在评论区求怎么写"才是行为证据——两组不得混层），按人群-场景-任务-痛点链呈现，附现有解决方案盘点（含"不解决"）。这份地图本身就有独立价值——很多人从没系统观察过市场需求。

每个信号按命题归属标注：需求侧证据（这个任务有人正被卡住）/ 承接线索（这个人被需要过）/ 市场存在证据（品类有商业行为）——三类分开，不合并计数。

路径B用户或已完成 Phase 4 能力审计的，在此附**承接资产摘要**（四层资产地图的浓缩版）：已成型可盘点的素材/相关经验/观察域。没有盘点过的如实写"承接资格待审计（验证后进行）"，不为了报告完整硬凑资产清单。

### 二、候选付费场景（最多 6-8 个——上限不是目标数量）

只有被事实支撑的场景才进入；证据不足时允许只有 2-3 个，甚至 0 个（直接写"当前证据不足以产出候选场景"）。不得为了满足数量补齐——模型很擅长生成看起来合理的场景，这恰恰是诊断报告最该警惕的能力。

不是"已被证明的付费场景"——大多数用户此时还没有商业证据。这是**值得进入付费验证的具体场景**。每个场景写全，落到**付款发生时刻**：

> 什么人 + 什么时刻（含时间压力）+ 什么任务 + 什么问题 + 现在怎么解决（含"不解决"）+ 为什么现有方式不够 + **为什么值得验证付费（这一判断目前有什么证据，尚无商业证据时必须写明"待验证"）**

"Excel很难"不是付费场景，"今晚要交20个表的合并"才是。每个场景按证据实况命名：已有商业证据 → "已有付费信号"；只有需求信号 → "需求场景"；零外部证据 → "候选场景（推断）"——不统一伪装成"真实付费场景"。证据只够 3-4 个时如实列出实际数量，注明"当前证据支持X个场景，少于建议区间，不为凑数拆分或虚构"。

### 三、定位假设（最多 3 个：主推 / 备选 / 探索——数量由证据决定）

**不同的定位假设**（目标人群或付费场景至少一项不同），不是同一产品的三个名字/功能/价格。**实际数量由证据决定：可以只有 1 个、2 个甚至 0 个。零证据不产生"探索方向"**——没有证据支撑的方向不进报告，不为报告完整创造候选。

**主推 = 当前证据下优先验证的定位假设，不等于已经成立。** 报告措辞用"目前最值得先验证的是X，原因是……"，不用"你应该做X"。

每个假设 12 个字段全部必填。**产品类字段（4/5/6）必须以假设身份书写**——进入 Positioning 不等于放松产品纪律，"产品载体：模板"不得写成"这个用户应该卖模板"：

1. 目标人群
2. 付费场景（对应第二部分哪个场景）
3. 个人连接现状（为什么是这个人，不是任何人——**非门槛化的诚实记录**：这个方向和你有什么真实接触/素材/经验。零连接如实写零，留给 Phase 4 审计和路径B使用，不作为进入条件）
4. 产品载体（**当前假设**的轻量形态：指南/清单/模板/题库/知识库/素材包/脚本库/AI工作流/诊断工具）
5. 具体 SKU（**当前验证版本**卖什么，一句话说清交付物）
6. 笔记切口（**用于验证该假设的**第一条内容从哪个具体问题切入）
7. 已验证信号（✅，格式：**信号 + 层级 + 证明的命题 + 来源**——如"评论区反复索取表格 → 需求证据层 → 证明'这个问题存在主动需求表达'→ 用户评论原话"，不得只写"✅需求证据"而不写它到底证明了什么命题）
8. 合理推断（🔶，标明推断依据）
9. 待实查信息（⏳，只放需要外部市场或实际行为确认的；用户可回答的一律回访谈，**待实查不是没问出来的垃圾桶**）
10. 替代方案检查（用户现在怎么解决、为什么不够、含"不解决"——回答"为什么现在付钱而不是继续凑合"）
11. 主要风险（版权/AI幻觉/合规/交付/同质化/未来适配 + **个人经营约束**：每周可投入时间/出镜意愿/客服承受度是否支撑该交付形态——访谈第四目标收集的约束在这里落点，不得收集了没处安放。三年后这个定位是更必要还是更边缘？答不上"更必要"的如实写进风险）
12. 证伪判据 + 7天验证动作（**至少一个失效条件**：什么事实一旦出现就放弃或缩窄；这7天该方向具体做什么）

**定位报告不给定价建议。** 价格是验证阶段的测试变量，不是定位结论。

### 四、只选一个方向先验证

明确写出："现在只验证【主推假设名】。" 判断依据必须是证据层级，不是"看起来最有潜力"。

**附中门硬阻断预检结果**：合规红线（**判产品行为不判行业**——涉医疗/法律/财务时看产品承诺是否进入受监管的专业判断/建议行为，"记录模板"可过/"饮食方案"阻断）/ 时间硬约束 / 绝对交付障碍（不可弥补的资质/资源障碍，可学习可工具的不算）——三条逐项写明通过或不通过；不通过的回到任务收窄链换形态重检，或回需求发现换方向。预检是轻检，只拦致命项；完整能力审计在验证 PASS 后进行，不在报告里提前执行。

**本节判断本身是一次决策类推荐，采用与访谈一致的格式**：**"➡️ 建议先验证X，因为Y（已有事实依据）。同意就答'同意'，不同意说你的理由。"**——它与报告结尾的"共享理解确认门"是同一原则（制造可反对物、防被动点头）在不同颗粒度的应用：推荐行针对单一决策，确认门针对整份报告结论，二者不重复。

备选和探索各附一句升降级判据（升降级判断留待真实信号出现时执行）。

### 五、七天最小商业验证

**七天只验证一个核心假设**（如"这类人是否愿意为这个具体解决方案付费"），不同时验证产品形态、价格、人群、内容形式和渠道——不要把七天做成一份小型创业计划书。

**验证成本匹配原则**：验证所需的最小行为，不得超过当前被验证的假设。为观察"家长是否愿意购买仿写训练"不需要先做完整PDF、50页课程、建会员、发30篇笔记——最小信息验证只需暴露一个问题看是否有需求表达（互动笔记/单篇内容）。提前建设既浪费成本，更污染实验：多投入的东西自己会替你解释结果。

**价格纪律**：价格可以作为完成核心验证所必需的测试变量（Day 6 报价观察反应），但**不得在验证过程中反复变动多个变量**；验证结果不能直接解释为"价格已被验证"——一次付款 ≠ 定价成立。

目标不是"7天做完产品"，是**用最低成本完成一次最小市场闭环**。按主推方向资产裁剪：

- Day 1 确定一个付费场景（写出付款时刻句）
- Day 2 找到真实用户 / 已有需求证据的触点
- Day 3 制作最小交付物（现成资产的裁剪版，不求全）
- Day 4 测试内容入口（笔记切口发布；若切口有多个候选，同用决策类推荐格式："➡️ 建议用切口A，因为B，同意就说同意"）
- Day 5 获取真实咨询（看私信/评论行为，不看点赞）
- Day 6 尝试成交（报价一次，观察反应——价格作为测试变量）
- Day 7 根据真实行为判断下一步

Day 7 四种去向：**PASS / 缩窄（NARROW）/ 重做（REBUILD）/ 停止（STOP）**。判据必须是**行为证据**，不是人为销量目标。验证结果回来后允许修正定位四变量（人/场景/问题/交付）再验证——产品是被用户行为逼出来的，不是一次设计出来的。

**Day 7 必附下一周期预告**（去向不同，下一步不同）：PASS → 完整能力审计（动作清单逐项判定，SKILL.md 状态四）；NARROW → 轻审计（只审被缩窄的方向）；REBUILD/STOP → 有实际交付动作才做优势沉淀复盘（记录本周期实际完成/卡住的动作——"优势从交付反推"的原始数据；零动作周期直接结束，不硬做复盘），几个周期后形成真正的个人优势画像。

**Day 7 额外必查一项：计划外使用。** 有没有人把产品/内容用在你没设计的地方？（买家只反复问某一个模块、私信问你顺带别的、把表格改成了你没想过的用法）——计划外使用可能直接暴露原定位没有覆盖的真实需求，**作为定位修正的重要输入**，优先于销量判据处理。归属说明：计划外使用是产品-市场匹配信号，**独立于三层证据体系**（不作为内容/需求/商业证据填入信号表），直接进定位修正循环。

### Validation Bridge（小红书执行件——很薄的一层，只管接口）

定位假设形成后、进入七天执行前，本 skill 交棒给执行层。这一节只定义**接口契约**，不复制执行能力：

**① 内容探针设计原则（最小信息设计，不是吊胃口）**：Day 4-5 发布的验证内容只暴露一个具体问题，保留足够判断价值的信息，但**不一次性交付完整解决方案**——目的不是制造悬念提高点击，而是让用户有机会主动进入下一步（问、要、求），从而观察需求表达。互动笔记（只发产品界面/框架图看是否有人"求链接"）是成本最低的需求探针。

**② 求链接类信号的证据边界（禁止越级）**：探针收回的"求链接""想要""怎么获取"类互动，只能支撑**"存在需求表达"（需求证据层）**——它不能作为 Day 7 判断"继续"的独立行为证据。继续的判据仍需商业证据层信号（真实询价对话/付款）出现；若求链接信号量级足够大、值得进一步投入，必须写明**下一步如何把需求证据推进到商业证据**（如：给求链接者一个真实报价，观察反应），不得把需求证据直接当结论用。

**③ 外部经验法则的拒绝（用户面免疫）**：用户提出的外部经验规则（"至少发够 N 篇再判断""至少坚持 N 个月""至少跑通闭环才许换"）**不作为停止判据**——若某方向已具备证据型停止条件（多种切口内容流量起不来+回访零意愿+已排除内容质量问题），无需等到任何次数门槛，可以更早停止；反之，即使达到任何次数门槛，证据不支持停止就不停。时间本身不是证据，发布次数本身也不是证据。

**④ 执行层的边界**：笔记结构/标题公式/封面设计/店铺运营/商品包装等平台执行细节**不在本 skill 范围内**，属内容执行层——请使用专门的小红书内容执行工具或方法补齐这一段。本 skill 只负责在这类工具产出之前，确认清楚**要验证的是哪一个核心假设、观察什么行为、什么证据状态触发哪个去向**。评论区观察作为例外（见 interview-guide 评论区信号采集表）——它是需求证据采集工具，属本 skill 范围。

### 共享理解确认门（完成状态行之前必过）

报告末尾用三句话回读核心结论：①定位一句话（人×场景×交付）②现在只验证什么③第一个具体动作。然后问用户：

> **"这三句里，哪一句与你实际情况不符、仍不确定、或者你会改？如果都准确，就直接说'确认'。"**

这不是走过场——用户被迫做一次非被动的检查动作，指出不符/不确定/会改的地方。用户改了哪句，就修哪句再确认；用户说确认，才算共识达成。目的不是制造异议，是让用户真的读。

### 完成状态行（报告末尾必写）

三选一，只声明证据状态，不自评质量：

- `已完成——证据充分，可按报告执行`
- `已完成，带开放问题——以下信息仍缺，答案会修正对应判断：…`
- `信息不足——缺X，补上后再出报告`

### 市场待实查项的可选现场核实

纯外部市场类待实查项（竞品价格/销量/类目规则），**在报告撰写过程中遇到时当场**问用户："这类信息我可以现在帮你查（只搜品类词），要查吗？"经同意后现场核实并标注来源，结果直接写入对应字段（不另外生成附加内容）；拒绝则保留待实查。用户本人可答的信息不适用此条。这不是报告定稿后的追加动作。

## 候选假设六组事实问题（访谈素材→候选资格的前置过滤器，不是报告写完后的事后复查）

**使用时机**：在决定把哪些方向写进三个候选**之前**，用这六组从访谈素材中筛方向——没过筛的方向不进候选，而不是候选写完后走形式检查。

1. **需求**：有成交案例 / 同行产品 / 用户主动求助 / 高频问题 / 搜索行为吗？（内容热度≠需求≠付费）
2. **个人连接现状（非门槛记录）**：这个方向与用户有真实接触吗（直接经验/素材/观察域/用户理解）？有则记录进"个人连接现状"字段；**不做"至少占一样"的资格筛选**——承接充分性在 Phase 4 审计判断。唯一动作：零接触的方向回 Phase 1 查是否领域漂移（观察域纪律）；不是漂移的（如平台公开信号驱动）如实记录"平台信号驱动，个人连接零"，留给 Phase 4。
3. **场景**：能否说清 谁+付款时刻+任务+问题+替代方案不足+为什么值得验证付费？
4. **产品**：能否转成轻量形态？（产品后置：最后一问。**产品可行性只能在需求成立之后检查，不能反过来证明需求成立**——"能做成模板"推不出"值得做"。）
5. **一人经营**：可标准化？可自动交付？工作量不随客户数线性增长？**硬过滤**：如果核心价值必须依赖持续的一对一人工判断，不得仅因存在需求就判定为合格的一人虚拟产品定位——必须进一步证明可通过产品化边界、标准化交付或受控定制降低人工依赖，否则不通过本组。
6. **验证**：7天内能完成一次最小市场闭环吗？

## 内容-产品闭环检查（主推假设必做）

用户问题 → 内容 → 用户搜索/阅读 → 产生进一步需求 → 产品 → 用户反馈 → 新的内容。发完就结束、天天重新想选题——内容可持续性存疑，写进主要风险。

## 资产化判断（主推假设必做）

**今天做出来的东西，明天还能继续产生价值吗？** 判断的不是产品形式（资料包形态本身无罪——一个资料包产生的用户问题、内容素材、使用反馈、需求数据仍可能积累），而是**这个产品是否产生可继续复用的知识、用户、内容或行为资产**。理想路径：第一次产品 → 知识资产 → 用户问题积累 → 第二个SKU → 内容库 → AI工作流 → 产品矩阵。确实无任何复用资产产生的方向，标"无积累性"并降级。

## 外部案例处理（防偏差）

用户提到"别人卖X卖得不错"类案例时，分三层记录，不得直接当作用户的机会：

- **案例事实**：它发生了（某账号低粉卖出大量知识产品）
- **可迁移机制**：分散知识 → 结构化 → 场景化 → 工具化 → 低边际交付
- **不可复制条件**：对方的人群积累、账号历史、具体内容、信任关系、资料来源

复制机制，不复制表面商品。
