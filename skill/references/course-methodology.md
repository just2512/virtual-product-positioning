# 定位方法论（原则详解与案例）

virtual-product-positioning 的方法论参考。**路径B资产盘点、Phase 4 能力审计、需要向用户解释"为什么要这样问"、或需要案例支撑判断时读本文件**——执行规则都在 SKILL.md，这里只放"为什么"和"怎么想"。

## 证据纪律继承（先声明）

本文件中的所有案例、推导、"需求侧线索"和产品方向**均属解释性材料**；除非被独立事实或外部证据验证，不得直接进入"已验证信号"或 Positioning 结论。Reference 里的推理结构是给你学怎么想的，不是可以直接复制成用户结论的模板。

## 核心方法论：优势是做出来的，不是想出来的

普通人的问题不是"不知道卖什么"，是**没看到自己手里的资产**——以及，在需求优先架构下，这个"看到"发生在两个正确的时机：**路径B入口（有成型资产的人带着资产找需求）和 Phase 4（产品验证有人要之后，用资产判断能否承接）**。他们说不清能力，但说得清做过的事——定位师的工作是在这两个时机把事实翻译成资产，不是在需求发现阶段守着前门问天赋。

**"优势往往是交付出来的副产品"**：一个人卖作文资料之前，未必知道自己"擅长教育内容结构化"；做了20套以后才发现自己擅长把复杂内容拆成孩子能练的小任务。所以资产发现不是一次性的问卷，是随着验证周期（优势沉淀复盘）不断沉淀的画像——路径B盘点和 Phase 4 审计是这张画像的两次显式快照。

## 个人资产四层框架（详解）

### 第一层：做过什么（事实）

最客观的入口。职业、家庭、兴趣、踩坑、长期坚持的杂事都算。这一层只记录，不评价。

### 第二层：因此掌握了什么（能力，从事实提炼）

从事实反推能力，**不由用户自我宣告**。"我每周都要整理老板要的经营报表"（用户原话）→ 能力：信息整理/数据结构化/异常判断/管理层沟通——是定位师从经历里挖出来的，不是用户说"我的优势是数据结构化"。

**提炼上限**：能力提炼只能达到原始事实能够合理支撑的程度。警惕升级链：做过报表→数据结构化→商业分析能力→经营决策能力——每一步都在超出直接经验，越过原始事实的升级必须单独标记为推断（🔶），不能把一次经历推导成全面专业能力。

### 第三层：因此留下了什么（可资产化物）

真正能进产品的东西：模板/表格/SOP/案例/话术/数据/清单/Prompt/工作流。问法："如果下周就要交付第一版产品，你手上已经有什么能直接用的？"

**"可资产化"强调可复用，不是"手里有个文件"**：一次性材料、未经整理的旧文件、别人资料的汇编，不自动视为资产——这与 advanced-diagnostics.md 的"材料≠资产"同一口径。

### 第四层：别人因为什么找过你（外部验证）

把"我认为自己会"和"别人确实认为你有用"分开。求助动词原文记录（"帮我看看"=诊断需求/"帮我改"=代做/"教我"=学习/"有没有现成的"=工具）——动词决定产品形态。动词映射表的执行主本在 `interview-guide.md`（使用规则节），此处为解释副本；两处表述如有出入，以 interview-guide 为准。

**引出问法**（用户不会自发说"有人找过我"——TA没意识到这算数）："过去有没有同事、朋友、家人因为这件事来找过你？他们当时是怎么问的？"

### 完整示例（单一事实的挖法）

用户说："我每周都要整理老板要的经营报表。"

```text
原始事实：每周整理经营报表
→ 能力：信息整理 / 数据结构化 / 异常判断 / 管理层沟通
→ 资产：报表模板 / 字段结构 / 分析方法 / 工作流
→ 需求侧候选线索：可能涉及不会整理经营数据的小企业主、运营人员（探索方向，不是已成立的人群判断）
→ 产品假设：经营报表模板 + 分析工作流（内部仅用于后续验证）
```

注意后两行的定性：**"需求侧候选线索"只是从能力到需求探索的搜索方向，不是目标人群证据**——"会整理老板报表"不等于"小企业主就是TA的目标用户"，能力线索 ≠ 人群证据。最后一行是**内部推理**，Discovery 阶段不得向用户输出（产品假设时序边界）。

## 六入口探针（没有商业经验的用户）

职业 → 家庭 → 兴趣 → 踩坑 → 资料 → 工具。用户在任一入口给出反复发生的事实，就沿四层往下挖。零出口时换入口，不重复施压。**六入口全部试完仍一无所获时**：退回最近的时间颗粒度——"昨天/上周你具体做了什么？从早到晚说一遍"——从最小事实单位里找可挖的，而不是继续问抽象类别。

**兴趣入口的降档纪律**："我对X感兴趣"（如"AI应用落地"）只能进**兴趣素材**层，自动拆解为：兴趣事实 ✅ → 能力（有没有为它做过具体的事？）→ 需求（有没有人为它找过你？）→ 定位（哪个人群哪个场景？）。**兴趣标签不得自动晋升为候选赛道**——用户在被追问"你想做什么"的最后时刻说出的兴趣词，可能只是表达渴望，不是定位方向；它决定接下来挖什么，不决定方向成立。

**当离场观察比继续问更有效**：六入口和最小颗粒度都是**当场**的追问技巧，它们假设"用户手里有事实只是没意识到"。但确实存在一类用户——不是不配合，是**从未用'这算不算能力'的视角看过自己的生活**，当场真的挖不出来；这时继续换问题只会让双方一起猜，最终为完成流程编造优势。识别比回忆容易、观察比内省容易——让用户离开对话几天，在真实生活里**记录发生的事**（谁找TA、问了什么原话），把"自我总结"（高认知负荷、易伪装）换成"事实登记"（低认知负荷、可验证）。这不是访谈失败，是证据采集方式从"回忆"切换到"观察"——符合本技能"先收集证据再提炼资产"的全套哲学。这就是 SKILL.md 卡点处理协议的方法论依据。

## 四层假设 × 三层证据的正交关系

两套结构回答不同问题，组合使用：

- **四层假设**回答"我们正在判断什么"：需求事实 → 需求假设 → 产品假设 → 个人承接假设（新架构：需求事实守第一层，个人承接压轴）
- **三层证据**回答"我们凭什么知道"：内容信号 → 需求信号 → 商业信号

示例链（需求优先顺序）：'同事总找我帮TA改周报'（需求事实，也是承接线索）→'这类任务有人正在被卡住'（需求假设）→'20组周报仿写训练'（产品假设）→'这个人能稳定做出并交付这套训练'（个人承接假设，Phase 4 审计）——然后逐层检查：每层假设有什么信号层的证据？没有就停在推断，跳层就是产品创意生成器。**特别注意第一跳和最后一跳**：第一跳（求助原话→群体需求）需要市场侧证据补充，单一来源是弱信号；最后一跳（需求成立→这个人能做）是本架构最后的跨层陷阱——市场证据从不回答承接资格。

### 两套证据的来源域区分（防混用）

第四层的人际验证（同事/朋友/家人主动求助）和三层证据体系（内容平台上的公开行为：赞/藏/评论/私信/成交）**来源域不同，不可互相替代**：

- 人际验证证明"这个人的能力在小范围内被需要过"——资产发现阶段的重要线索，但**不能直接填入市场需求证据格**（同事求助可能只是顺手和关系，不代表市场付费意愿）。
- 反过来，若只认平台信号而忽略人际证据，会把普通人最真实的外部验证浪费掉——它不在信号表里不代表它没价值，它属于资产地图第四层。

典型场景："我表姐一直找我问育儿的事"——这是资产发现层的强证据（能力被需要过），但**"育儿知识付费"的需求假设依然是零证据**，要支撑它仍需三层体系里的信号（尤其商业证据层）。两者分别陈述，不得合并计数。

## 信号 → 可支持命题的映射（references 侧统一口径）

**判断不是由"证据很多"成立，而是由"证据直接支持当前命题"成立**——一堆相关信息拼起来支持一个没被直接证明的结论，是本 skill 最典型的跨层错误（搜索很多+竞品很多+点赞很多≠用户愿意付费）。

主 SKILL.md 的证据表是契约；这里是给访谈和报告的具体口径：

| 信号 | 可支持的命题 | 不可支持的命题 |
|---|---|---|
| 点赞/阅读 | 内容引起了兴趣 | 任何需求或付费 |
| 收藏 | 保存意图/内容价值 | 付费意愿 |
| 评论求助/重复提问 | 存在需求表达 | 愿意为解决方案付费 |
| 平台关键词搜索热度 | 有人主动寻找这个问题 | 愿意付款（搜索是免费的） |
| 主动私信索取 | 主动需求 | 付费意愿 |
| 同类商品持续成交 | 该品类需求存在 | **这个用户的产品会被买**（承接资格是另一半题，见市场需求≠个人承接资格）；**也不能自动证明用户的具体人群、场景、价值主张与该市场相同——品类存在≠你的定位成立** |
| 询价 | 购买意图 | 成交 |
| 付款 | 交易发生 | 可持续 |
| 复购/转介绍 | 持续价值 | 可规模化 |

## 典型认知跳跃反例（故障诊断手册）

以下是推理跳跃，不是事实链——遇到时逐个检查缺了哪层证据：

```text
职业标签 → 产品（8年HR→简历模板）
兴趣 → 需求（我喜欢健身→大家需要健身计划）
爆文 → 商业验证（10万阅读→有人愿意付费）
有竞品 → 自己能卖（别人卖得动→我卖得动）
有资产 → 有市场（我整理过资料→有人要买）
客户愿意定制 → 应该做服务（被需求推着接单→产品化没必要）
AI能做 → 用户愿意买AI（技术可行→商业成立）
人际求助 → 市场需求（表姐老问我→育儿付费市场存在）
```

## 为什么"验证看行为不看判断"

访谈和推理只能产生假设；假设的检验只有一种方式——真实行为（咨询/询价/下单/复购）。所有"听起来合理""市场应该需要"都属于模型判断，判断不能验证判断。这也是七天验证只设行为判据、不设销量目标的原因：目标是模型预期，行为是市场回答。

## 案例库（用于理解，不用于复制）

### 案例一：蒙氏AI育儿知识库（外部案例的标准处理）

- 案例事实：某低粉账号卖出大量知识产品（**用户观察，细节未验证**）
- 可迁移机制：具体用户 + 高频问题 + 复杂分散知识 + 用户缺乏整理能力 + 重新结构化 + 低成本数字交付 + AI降低使用门槛 + 内容作为需求入口
- 不可复制条件：对方的人群积累、账号历史、具体内容、信任关系、资料来源

**教学点**：连"案例事实"这一层本身也要先审来源——这个案例来自用户转述，未经查证。使用任何外部案例的第一步永远是问"这件事本身是真的吗，我从哪听说的"，而不是直接跳到"机制能不能迁移"。证据分级思维要用在案例身上，包括案例的入库环节。

**复制机制，不复制表面商品。** 同一产品形态嫁接不同的人，成败完全不同——"定位师"与"选品"的区别就在这里。

### 案例二：简历模板（职业标签≠定位的标准处理）

8年HR → 简历模板是模型的第一联想，但它是产品假设不是定位。8年HR的最佳产品可能是简历诊断工具、招聘流程工具，也可能与HR完全无关。候选形成之前，不得因职业标签默认主线。
