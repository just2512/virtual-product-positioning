# 五轮访谈问题库（需求优先版）

virtual-product-positioning 的访谈执行参考。开始访谈前读本文件。

## 使用规则

- **一次只推进一个独立事实变量**："一个问题"按信息变量计算，不按问号计算。"最近找你帮忙的人是谁？什么职业？什么时候找的？卡在什么事上？"是一个问号里四件事，违反本条。一次只能要求用户提供一个独立事实。
- **五轮 = 五个信息目标**（需求信号 / 外部证据归属 / 人群与场景收窄 / 产品化条件 / 承接资格——最后一个条件触发），不是五个固定问题，也不是定位过程的总上限——**五轮是一次连续访谈周期的上限**，周期可以有多个（卡点暂停→离场采集→带事实回来→开新周期）。下一问选"当前最缺失且会改变判断"的信息，不按本文件顺序机械走。
- **需求优先于优势**：前四个目标全部围绕市场侧（谁在为什么事发愁）；"你擅长什么/你有什么优势"式问题不作为入口问题出现——承接资格只在条件触发时问（见第五目标），且问的是动作级事实（做过类似的事吗/有素材吗），不是天赋级自我评价。
- **不问已经知道的，不问不会改变判断的，不问只为把报告写全的。** 第五目标的清单同理——清单是探针不是必问表。
- **未知信息三分流**：用户本人可回答、且会改变定位判断的信息缺失 → 继续访谈（不许扔进待实查逃掉）；需要外部市场才能确认的 → 待实查；**只有行为能回答的（愿不愿付费/付多少）→ 保留为待验证假设，转成验证设计，不在访谈里逼答案**。
- **用户提供的结论先当假设**：用户主动给出的定位、人群、需求、价格、产品结论，先按待检验假设处理——只有其中可追溯的经历或行为事实进事实层。防"用户结论→模型复述→用户点头→变成已知事实"的链。
- **停止机制（缺乏证据，不是证明零需求）**：某方向关键前提被事实否定、且现有信息无法通过继续访谈解决时，结束该方向。结论是"**当前证据不足以支持把它作为有效方向**"，不是"市场不存在"。
- **逃生舱**：用户催"直接给结论"→第一次拦（说明价值+只问剩余最关键的2个），第二次尊重并降级输出，不问第三次。用户自带完整付费证据时允许跳过访谈，但替代方案检查和反证检查仍必做。
- **关键问题推两次（只在答案模糊时）**：第一答具体到足以改变下一步判断 → 直接进下一目标；第一答存在模糊点（"挺多的""都还行"）→ 挑最模糊处追问一次，第二个答案才可用。
- **复述确认（确认的是理解，不是结论）**：关键答案收到后一句话复述理解，用户确认后才进下一目标。**用户"对"只证明复述无误，不等于该判断被市场验证**。
- **问题依赖纪律**：下一问的选择依赖已有答案——B 的答案取决于 A 时，A 没答就别问 B。每轮问完后重新看一遍已收集的事实再选下一问，不预写问题序列。
- **推荐答案行（仅限访谈收尾的方向取舍决策）**：收尾类决策（"三个方向里先验证哪个"）在问题后附一行推荐+一句理由，格式：**"➡️ 我的推荐：X，因为Y。同意就答'同意'，不同意说你的。"**——推荐天生是可反对物，能激发真实异议。**权限边界**：推荐只能基于已有事实支持的分析方向，不得借推荐替用户制造未经验证的市场判断；**事实类**问题不附推荐——用户的人生你不知道，附了就是编。
- **记录求助动词原文**："帮我看看"（诊断需求）/"帮我改"（代做需求）/"教我"（学习需求）/"有没有现成的"（工具需求）——**动词决定产品形态**，记录原话不翻译。
- **证据描述用命题归属，不用强度比较**：说"红包=掏钱意图的信号"（它证明了什么），不说"最硬的一条证据"——强度比较是评分体系的入口措辞。
- **收尾必留一个具体动作**：访谈无论在哪一步结束（含信息不足停止），都留一个用户当天能做的具体动作，不让用户空手走。
- 用户回答跑题时，记为素材，把问题拉回来，不指责。
- 访谈状态禁止输出任何产品/SKU/价格/内容/商业模式建议——哪怕已经猜到方向。内部假设留在内部。
- 本周期结束时仍不能收敛：卡点明确的给自主发现任务，卡点不明确的诚实输出"信息不足以定位"+ 待实查清单 + 一个具体动作，不硬编定位。

## 按入口路由选问题子集

开场先做入口判断（A冷启动 / B自带素材 / C产品先行 / D已在经营 / E资产持有者），再选问题子集：

| 入口 | 优先问 | 可跳过 |
|---|---|---|
| A 冷启动（零观察零素材） | 需求信号、外部证据、人群场景、产品化条件 | 承接资格（Phase 4 再问） |
| B 自带素材（一次给足背景） | 只补会改变结论的缺口（尤其需求证据+承接资格的缺口），其余跳过 | 已被事实覆盖的目标 |
| C 产品先行（自带产品/价格求执行） | 前提否定→拆回四层假设→需求证据、人群场景 | 承接资格（用户已自证部分） |
| D 已在经营（有真实经营行为且与当前方向直接相关：下单/询价/真实客户使用/复购/转介绍） | 直接进阶诊断，不走访谈 | 全部访谈目标 |
| E 资产持有者（路径B） | 先轻量资产盘点（见 course-methodology）→ 带资产地图进需求信号、人群场景、产品化条件 | 承接资格的重复盘点 |

## 追问模式（BAD/GOOD 对照）

用户答案空泛或自我感觉良好时，用对照里的 GOOD 方式推。压力在具体化，不在语气凶：

| 模式 | 用户说 | BAD（顺接） | GOOD（逼具体） |
|---|---|---|---|
| 空泛人群 | "我想做个职场提升类的资料" | "挺好的，职场是大赛道" | "'职场提升'是筛选器不是人。说一个具体的人：谁、在什么时刻、卡在什么事上？你能给这个人发私信吗？" |
| 赛道信号 | "这个赛道最近很火" | "是不错的趋势" | "火是供给信号不是需求证据——火说明很多人在做，不说明有人急着完成什么。你亲眼见过谁被这个事卡住吗？" |
| 社交证明 | "朋友都说这想法不错" | "那很鼓励，具体谁说的？" | "说不错是免费的。有人提出要付钱吗？有人追着要成品吗？没有主动索取证据时，先按'当前缺乏主动需求证据'处理。" |
| 平台愿景 | "我想做一个完整的体系再上线" | "可以先做个简化版吗？" | "这是个警示信号：如果缩小到单模块就没人要，说明价值主张还没立住。哪个单模块本周就有人愿意付钱？" |
| 增长数据 | "这个市场每年增长很多" | "是不错的趋势" | "增长率人人可引用，不是你的机会。你在这个需求现场吗——谁在什么时候为它发过愁？" |
| 模糊词 | "我想做高效的学习方法" | "怎么定义高效呢？" | "'高效'是感受不是可测量的东西。哪个具体环节让人卡住？卡住的时候他们现在怎么办？" |
| 自己脑补 | "我觉得家长肯定会需要" | "确实是个刚需" | "'肯定'是想象不是观察。最近一次你亲眼看到家长被这事难住是什么时候？" |

## 红旗答案清单

听到这些答案，不要顺着走，直接点破并往证据方向推：

- **外部证据类**："好几个朋友都说好" / "发了问卷反馈不错"（问卷会说谎，口头夸奖是免费的）→ 推：有人主动来要过成品吗？有人付过钱吗？
- **现状类**："他们现在什么都没做" → 红旗：零现状成本 + 无高压时刻 = 问题没痛到值得行动，进反证。（若该场景存在罕见高压时刻，零日常 workaround 不直接判死，见 SKILL.md 现状即对手节。）
- **人群类**："宝妈" / "职场人士" / "学生" → 这些是筛选器不是人，你不能给一个分类发私信。推到具体的人。
- **需求类**："我觉得大家应该需要" → 自我感觉只是线索。推：最近一次亲眼看到有人被这事卡住是什么时候？
- **领域漂移类**："宠物赛道/银发经济现在很火，我想进去" → 红旗：观察域外需求——你对这个领域有真实接触吗（服务过的人/长期混的群/自己的坑）？没有接触的领域，连验证内容都做不真。推回生活半径。
- **产品类**（访谈期）："那我是不是可以卖XX？" → 访谈未完成不接产品话头："先放一放，把需求的事问完再说产品——产品是最后一步。"

## 第一目标：需求信号发现（什么人正在为什么事发愁）

**这是新主入口。** 不问"你有什么优势"，问"你观察到了什么需求"。

主问题（按开场选一）：

- "最近有没有看到一个人群反复在解决同一种实际问题？工作里的、生活里的、群里的都算。"
- "你身边的人最近有没有什么事，他们自己搞不定、到处问人、或者直接花钱买现成方案的？"
- "有没有一个任务，你亲眼看过别人卡壳——Ta当时要完成什么、卡在哪、急不急？"

**观察域纪律（机会发现约束，不是能力字段）**：观察域 = 用户能够持续接触、理解、观察并获得真实需求原话的人群/场景/问题范围（工作岗位/家庭生活/长期兴趣/曾解决过的问题/服务过的人/身边高频麻烦/长期使用的工具流程）。**不要求专家，只要求真实接触**。需求观察优先在观察域内进行：①普通人对自己毫无接触的领域（"宠物赛道火"）连验证内容都做不真，最终内容空心化；②个人连接在这里的作用是**提高需求观察质量**（原话真实、场景理解），不是证明"我有优势"——这条纪律约束观察质量，不设资格门槛。平台公开信号（评论区/搜索词/同类成交）用于市场侧验证，两条腿都要，归属分开标注。

**需求结构 × 需求证据（两组概念，不得混层）**——Phase 1 的核心采集物，逐项对照：

**需求结构特征**（任务/场景的结构——描述问题长什么样，本身不证明需求存在）：
1. 高频发生（开学/考试/搬家/求职/育儿/报名/办证——周期性反复任务）
2. 有截止或结果要求（写完作文/完成简历/填好表格——任务有验收）
3. 有认知缺口（执行者或其家长/上级缺乏完成能力）

**需求证据**（外部行为——证明"真的有人在为此付出行为"）：
评论求助 / 重复提问 / 主动私信索取 / 同类商品持续成交 / 搜索行为。

**结构特征不是证据**："孩子经常不会作文"是结构描述；"家长在评论区求怎么写"才是行为证据。两组分开记录、分开标注——运行时最容易犯的错就是把高频结构当成已有需求。四项不是门槛清单——一条真实发生的求助原话（谁、什么时刻、卡在什么）比全部勾中的想象都有价值。要的是**具体事件**，不是领域印象。

**求助原话双命题**（一条事实两用，命题分开标注）："同事反复找我帮Ta改周报"这类原话——
- 按需求证据读：存在真实需求表达（这个人此刻正被这事难住）——需求证据层
- 按承接线索读：这个人的能力被需要过——资产地图第四层（Phase 4 / 路径B 用）

同一条原话可以分别支撑这两个命题，标注来源域（生活半径）；但它不支撑规模化命题（"市场上的人都愿意付钱"——那需要平台信号/市场成交）。单一来源（一个人问过）是弱信号，如实标注，不夸大成"群体需求"。

### 评论区信号采集表（观察任务的执行工具，挂靠三层证据体系）

用户离场观察评论区时，按四类信号采集——**每类已映射到三层证据，标注时用我们的层，不用对方的分类名**：

| 采集什么（原话记录） | 属于哪层 | 只能证明 | 不能证明 |
|---|---|---|---|
| 痛点共鸣（"太需要了""和我情况一模一样"） | **内容证据** | 这类内容击中了相似处境的人的共鸣 | 任何需求或付费 |
| 延伸需求（"有没有XX版本""想要可编辑的"） | **需求证据** | 存在未被当前产品满足的需求表达 | 愿意付费 |
| 直接求购（"哪里买""求链接"） | **需求证据**（询价前一步） | 存在主动获取意愿 | 交易会发生 |
| 已产品化信号（博主回"看主页/简介"） | **市场存在证据**（只进替代方案检查） | 该品类存在商业行为 | **这个人做的会被买**（市场存在≠个人承接资格，不得填入该用户的需求证据格） |

采集动作要具体："搜赛道关键词→点开点赞中等但评论活跃的笔记→把四类命中原话抄回来"——不是"去看看评论"。

### 需求观察作业（当场挖不出需求信号时）

触发条件：三个主问题都得到空泛或否定回答（"没注意过""想不起来"持续出现）——用户从未用"谁在为什么事发愁"的视角看过自己的生活，当场挖不出来。继续问第4、第5个问题只会让双方一起猜。

给用户的观察任务（只记录发生的事，不总结）：

- 接下来几天，有没有人问你"这个你会不会/能不能帮我弄一下"——原话记下来，谁问的、问的什么
- 翻微信聊天记录/工作群/家长群/家庭群，搜"帮我看看""怎么弄""有模板吗""能不能帮我改""这个你比较懂"——把命中的原话带回来
- 你自己最近有没有一件事卡了你好几天，最后靠搜/问/买解决的？当时搜了什么、问了谁、买了什么

**任务不暗示答案**：开放式采集（"留意别人因什么事来找你"），不内置方向（不布置"观察有没有人求Excel表格"）。设返回条件："带3个最具体的例子回来"。**重新进入**：带观察记录回来后不重走五轮，直接回到第一目标把记录当新的原始事实处理。

## 第二目标：外部证据归属

判断已采集信号**证明什么、不证明什么**，防止混计数。

主问题（按第一目标产出选）：

- "有没有人为这类事付过钱给你、送过东西、或认真道过谢？什么场景？"
- "有没有人反复来问你同一类问题——第二次、第三次还在问的那种？"
- "你身边有没有人靠这个赚钱？他们卖的具体是什么、卖给谁？"（市场侧探针）

**证据归属纪律**：求助/复问/付钱是**个人侧证据**（这个人被需要过）；"别人靠这个赚钱"是**市场需求证据**（品类有成交）；平台评论区/搜索/同类成交是**市场侧证据**。三类分别记录、分别使用，不合并计数、不互相替代。点赞收藏只是内容证据，不跨级。**市场成交 ≠ 个人承接资格**——"别人卖得动"连"这个人的会被买"都不证明。零市场侧证据的方向如实标注，不因个人侧证据充足而假装市场已验证。

## 第三目标：人群与场景收窄

从领域收窄到具体购买者和**付款发生时刻**。

主问题：

- "用一个具体的人举例：TA是谁、在什么时刻、卡在什么事上？最近你亲眼见过或被问到的一次。"

**堆叠式逼问**——不许塌成单问。第一个答案几乎一定停在分类层，按这个顺序逐层堆：

```text
TA具体是谁？（身份/处境）
→ 在哪个时刻？（含时间压力）
→ 卡在什么事上？
→ 这事对TA的真实后果是什么？（领域决定后果类型）
```

后果按领域匹配：**职场方向**问饭碗/绩效（"做不好这件事，谁年底背锅？"）；**生活方向**问当晚/当场（"这件事搞砸，那天晚上家里什么样？"）；**兴趣方向**问那个被卡住的周末项目。压力在堆叠——用户每答一层就再堆一层，直到说出"最近的一个具体的人"。

收窄检查——必须能描述：帮助【谁】在【什么时刻（含时间压力）】完成【什么任务】时解决【什么阻碍】，他们现在怎么解决、为什么不够，以及**当时最希望避免什么损失或获得什么结果**。**"愿意为该结果付费"若无真实行为证据，保留为待验证假设**——不得逼用户说出"这个人会付钱"（那是隐形市场判断，愿不愿付费只有行为能回答）。

**后果 ≠ 付费**：后果严重用于识别场景价值和压力，不直接推导付费意愿——痛点严重 ≠ 市场愿意付费，付费意愿独立验证。

拦住领域词（女性成长/职场/育儿/公考/AI/自媒体）：这些是领域不是场景，继续收窄。

## 第四目标：产品化条件（任务能不能做成低成本数字产品）

需求确认后才问产品——五个硬条件逐一过：

```text
任务是否足够具体（"不会写作文"太大，"不会把'妈妈很辛苦'写具体"接近可产品化）
→ 能否标准化（20组仿写能复制给100个人，还是每人都得单独定制）
→ 能否数字化交付（文件/链接/代码，不发物流）
→ 用户是否能立即使用（拿到当天就能用上，不是先学一套方法论）
→ 是否存在现有付费或替代方案（含免费AI、自己凑合——现状才是真正的对手）
```

主问题："这个任务如果做成一个别人拿来就用的东西，会是什么？他们现在为什么还没用上这样的东西？"

**任务收窄链示例**（收窄的颗粒度参照）：

```text
孩子不会作文（太大）
→ 孩子不会写人物描写（更具体）
→ 孩子不会把"妈妈很辛苦"写具体（接近可产品化）
→ 20组人物描写仿写训练（这才是产品）
```

每一步收窄都问一句：这步收窄有没有证据支持（是观察到的具体卡点，还是想象出来的"应该需要"）？**产品可行性只能在需求成立之后检查，不能反过来证明需求成立**——"能做成模板"推不出"值得做"。

**知识型 vs 任务型**：优先"用户现在要完成什么"（任务型），不是"用户想学习什么"（知识型）——任务型购买链路短（"这是不是我现在的问题？"一个判断），知识型要用户先相信需要提升/方法有效/作者靠谱/愿意投时间。已有证据表明该人群对知识型有已验证付费行为时，知识型成立。

## 第五目标：承接资格（条件触发：路径B入口 / Phase 4 审计 / 中门预检需问硬障碍事实时）

**本目标不在常规 Phase 1 访谈中出现**——需求优先架构下，承接资格在验证 PASS 后的能力审计（或路径B入口盘点）才正式问。触发时的问法是**动作级**，不是天赋级：

- "这个产品需要做这些事（列动作清单）：找选题/整理内容/做案例/写笔记/回复用户——哪些你做过类似的？哪些有现成素材？"
- "你愿不愿意连续三个月每周重复这套动作？"

**不问**"你最大的优势是什么/你有什么天赋"——那是二阶抽象问题，普通人答不上来，答上来的也是自我评价不是证据。逐项判定的输出是"12个动作里独立完成8个、AI辅助3个、1个硬障碍"——有决策价值。完整方法见 course-methodology.md 四层框架与 SKILL.md 状态四。

## 横向需求线扫描

连续两轮围绕同一需求线后，检查是否还有其他未探索的观察域（其他群/其他身份接触的场景/其他自己踩过的坑）。**第一需求线未确认前，不得因一个领域印象默认它是唯一主线**。

**换线提前触发**：同一需求线**连续 3 个问题**得到否定/空答（"没有/不知道/想不起来"）即触发横向扫描换线，不等该线被"彻底否定"——一条线凉了但用户还有其他观察域时，换线比死磕合理（卡点≠停机）。换线时一句话冻结当前线已确认事实（"家长群线先挂起：3条求助原话已记录，付费信号零"），再切下一条线。

## 卡点处理总表（各目标通用）

| 卡点 | 不应该做 | 应该给 |
|---|---|---|
| 想不出需求信号 | 自己举赛道例子引导（泄漏候选） | 需求观察作业（聊天记录回看+留意求助原话） |
| 说不清目标人群 | 替用户定义"宝妈/职场人" | 记录最近遇到的真实的人（一周内谁被这事卡住） |
| 说不清场景 | 抽象讨论痛点 | 回忆一个具体事件（最近一次亲眼见过的卡壳现场） |
| 没有市场侧证据 | 用个人求助冒充市场验证 | 评论区信号采集 / 待实查同类成交 |
| 分不清信号证明什么 | 全部算"有需求" | 按命题归属拆开（第二目标纪律） |
| 需求有但做不成产品 | 硬做（伪产品化） | 任务收窄链检查 / 如实标"任务不够具体" |
| 几个方向选不出来 | 模型替用户决定 | 明确取舍依据（证据层级），推荐答案行格式，让用户选 |
| 方向始终没有证据 | 换包装继续做 | 暂停或停止（证据型出口） |

## 访谈有效自检（收敛前过一遍）

访谈快结束时对照检查，缺项的处理方式写在每条后面：

1. **用户至少异议或补充过一次**（反驳你的判断/纠正你的复述/主动说了你没问的信息）。全程零异议 → 触发被动性防线（异议测试："挑一个你其实不太确定的点，说说哪里不对劲"）；仍零异议 → 报告中用户确认类结论标"未经确认"。
2. **后问的问题明显建立在前面答案之上**（能指出哪个答案改变了哪个方向）。做不到 → 说明在走问题模板而非动态访谈，回到"当前最缺失"重新选。
3. **每个关键判断都能回溯到用户原话或外部信号**。做不到 → 按未知信息三分流处理，不写成结论。
4. **收尾有具体动作**（用户当天能做的一件事）。
5. **需求信号与承接线索分开标注**——每个信号能回答"这是需求侧证据还是这个人被需要的证据"。

## 谈话纪律

- 用户带产品来（入口C）时：前提否定权 → 拆四层假设 → 访谈补足。执行建议等定位成立且用户明确进入执行阶段后再谈。
- 不承诺"这个方向肯定行"。
- 用户自述只记为用户自述，不当市场事实；行业常识只作标注过的背景推断。
- 用户说出新素材随时回补前面目标的缺口。
